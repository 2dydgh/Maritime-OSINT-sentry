# 로컬 의사결정 기록 운영

현재 구현은 한 서버에서 SQLite에 저장하는 로컬 서비스입니다. 클라우드 계정이나 유료 자원을 만들지 않습니다. 공동 운용 인증/권한, 지형 제약 시뮬레이션은 아직 적용하지 않았습니다.

## 저장과 백업

```bash
.venv/bin/python -m backend.data_platform.operations status
.venv/bin/python -m backend.data_platform.operations backup var/backups/decision-checkpoint
```

`status`는 DB·WAL 크기와 테이블 행 수를 조회합니다. `backup`은 기존 경로를 덮어쓰지 않고 SQLite 온라인 백업 API를 사용합니다. WAL에 남은 커밋 데이터도 포함하고 `integrity_check`, SHA-256 manifest, 검토 기록이 참조하는 비교 존재 여부를 검증합니다. DB별로 일관된 순차 백업이며 전체 시스템의 한 시점 스냅샷은 아닙니다. 검증에 실패하면 성공 manifest를 만들지 않으므로 실패한 디렉터리를 완성 백업으로 취급하지 않습니다.

원본 자동 삭제는 없습니다. 제안/검토/비교는 계속 보존하며 후속 관측은 제안당 최신 1,200개로 제한합니다. 장기 보관 주기·삭제 승인이 정해지기 전에는 용량을 점검하고 별도 저장소에 백업 사본을 보관해야 합니다.

복원은 서버를 중지한 상태에서 현재 DB를 먼저 별도 보관한 뒤 진행합니다. manifest의 SHA-256을 검증하고 watch/scenarios를 같은 백업 묶음으로 복원합니다. 이전 DB의 WAL/SHM 파일을 새 DB와 섞지 않도록 새 데이터 디렉터리에 복사하고 `WATCH_DB`, `SCENARIO_DB`, 필요 시 `DATA_PLATFORM_DB` 경로를 그 디렉터리로 지정해 기동합니다. 운영 DB를 덮어쓰는 자동 복원 명령은 제공하지 않습니다.

## 공동 운용 전 남은 작업

- OIDC 등 로그인 제공자와 운영 주체를 결정하고 서버가 검증한 사용자 ID를 감사 기록에 사용
- 읽기 전용 / 검토·집중 추적 판단 / 계정·보관 관리 권한을 서버에서 강제
- 현재 브라우저 `client_id`는 실행 영수증 연결용이며 인증 수단이 아님
- HTTPS, 비밀정보 주입, 백업 저장소·보존기간, 복구 훈련
- 다중 인스턴스 실행 전 제안·비교 저장을 공유 트랜잭션 DB로 이전하고 수집/분석 워커를 단일 실행 또는 분산 락으로 보호

바로 클라우드로 옮겨도 위 기능이 자동으로 갖춰지지는 않습니다. 현재 compose 데이터 플랫폼 볼륨에는 세 DB가 들어가므로 단일 서버 배포의 저장 경로는 마련되어 있습니다.
